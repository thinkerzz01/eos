Thinkerzz EOS · Design Blueprint

A modern, interactive UI for every role

A research-backed redesign plan — layout, data-visualisation, motion and interaction — for each tab of Admin, Manager, Teacher and Student. Nothing here is built yet; this is the spec to approve, then implement in phases.

🟢 cheap win 🟡 medium 🔴 investment Stack: Next.js + Tailwind + Recharts + Motion

1 · The idea in one screen

“Modern” here is not new colours — it is hierarchy, live data, motion and the ability to act in one click. Three things separate a product people say wow to from one they tolerate:

Glance

The first screen answers “is anything wrong?” in 10 seconds — a row of KPI tiles with trend, then the one chart that matters, then an attention feed. No scrolling to see status.

Motion

Count-up numbers, a staggered card entrance, hover lift, skeleton loaders, and charts that draw in on load. Subtle and fast reads as premium; bouncy and slow reads as a toy.

Act

Click a KPI or a funnel stage to drill into the underlying list. A Cmd-K palette to jump anywhere. Quick-actions on row hover. The dashboard becomes a tool, not a poster.

The honest gap today: the backend is strong and the current UI is clean, but it is mostly static cards and read-only tables. It informs; it does not yet feel alive or let you act from the overview. That is exactly what this plan fixes — and most of it is cheap wins.

2 · What the best systems actually do

Synthesised from TeachWorks, Fedena, Classe365, Gradelink, Edmingle, Teachmint, Skolaro, OpenEduCat/Odoo, Toddle, and admissions CRMs (Digistorm, LeadSquared).

  • Left sidebar wins — near-universal in this category, grouped into People / Academics / Finance / Comms / System, with a slim top bar for search + notifications + account.
  • Dashboard = widget grid, not one chart — a top row of KPI stat tiles, then charts, then lists/feeds. TeachWorks & Fedena make widgets toggleable; Classe365 & Skolaro make the dashboard customisable per role.
  • Each role’s landing leads with that role’s #1 metric — Admin: revenue/collection + pipeline + alerts; Teacher: “my today” (classes, grading, attendance to mark); Student/Parent: grades/progress first, then schedule, attendance, fees (Gradelink, Classe365).
  • Fees canon (Teachmint): collected / pending / trend-over-time. Admissions canon (Digistorm): a funnel with per-stage conversion %, filterable by source.
  • Alerts + rules sit on top of passive dashboards — poor-grade emails, absentee push, scheduling-conflict detection, auto-dunning. “At a glance” includes proactive attention items, not just charts.
  • One dataset, several lenses (Odoo) — list ↔ calendar ↔ kanban ↔ graph toggle on the same data; a great pattern for Students, Leads and Schedule.

3.3 · KPI stat-tile anatomy

The highest-ROI element. Each tile = headline number + one of {trend arrow %, period delta, sparkline} — never all three. tabular-nums on every figure. Colour by sentiment: green-up is good for revenue/attendance, but invert for “at-risk” or “overdue” (up = bad). 🟢

3.4 · Chart house-style

Default chart = smoothed area-line with a dashed target line, gradient fill for single series, hover crosshair + formatted tooltip, and a 7d/30d/12mo toggle. This satisfies the line-graph preference for attendance, fees, revenue, homework rate and grades. Engine: Recharts via the shadcn Chart wrapper (themeable via CSS vars → instant dark mode). 🟡

MetricChartWhy
Fee collection / revenueArea-line + dashed targetTime trend; same currency unit = single axis, no dual-axis trap.
Attendance / homework rateLine (7-day rolling avg), 0–100% axisSmooth the daily noise; overlay an 85% goal line.
Leads → Demos → EnrolledFunnel + per-stage %Purpose-built for sequential drop-off; pie hides conversion.
Teacher load / capacitySorted horizontal bars + capacity markerComparison across named people, not a time series.
Performance distributionHistogram / stacked status barShows the shape — where the at-risk cluster sits.
Single completion metricRadial progress ringGlanceable; % in the centre. Never several rings side by side.

Interaction budget per chart: tooltip · crosshair · period toggle · legend toggle · click-to-drill-down · a fast (~400ms) draw-in that respects prefers-reduced-motion. Nothing more.

3.5 · Motion system

Premium (do)

  • Hover lift: ~2% scale / 1–2px + stronger shadow, 150ms
  • Count-up KPI numbers on first paint (~0.8s ease-out)
  • Staggered card entrance (40–60ms) — once on load
  • Skeleton loaders that mirror the real layout (loads >0.5s)
  • Chart draw-in on mount; a barely-perceptible “live” pulse dot

Gimmicky (avoid)

  • Bouncy spring overshoot on everything, >200ms
  • Re-animating numbers/cards on every data refresh
  • Animation for sub-300ms actions
  • Motion with no informational purpose
  • Multiple 3D assets competing with the data

3.7 · Empty states & the “wow on first login”

A brand-new admin logs into a dashboard with no data — the highest-stakes screen. Every empty state = what will appear here + why it matters + one obvious CTA, with an illustrated preview of the populated state (beats “No data yet”). The “wow” stack, all cheap/medium: populated bento grid + count-up KPIs + staggered entrance + a warm empty-state illustration on still-blank sections + a Cmd-K hint. 🟡

3D / illustration: use sparingly — one spot per page, at empty states, onboarding, and the login/welcome card. Lightweight SVG, lazy-loaded. It must never push the primary CTA below the fold (fails at 375px).

4.2 · Admin tabs

Students 🟢

Add a list / kanban-by-status / at-risk view toggle over the same data. Row hover reveals quick-actions (schedule, message, voucher). Each row shows a health chip (Green/Amber/Red) + a tiny attendance sparkline. Detail drawer opens in place (no full page). Top strip: total / active / at-risk / avg attendance KPI tiles.

Teachers 🟢

Cards or table with a capacity bar + load % per teacher, sortable by load / pay-rate / subjects. Click → profile with today’s schedule and a small “classes taught / students” trend. Surface “available to take another class”.

Leads & Demos 🟡

Lead with the admissions funnel + per-stage conversion %, filterable by source. Below, a pipeline kanban (New → Contacted → Demo booked → Won/Lost) with drag between stages. Lost-reason mini-bar. Rep activity metrics.

Booking & Schedule (Demos) 🟢

A calendar + list toggle. A conflict detector banner when a teacher/room double-books (TeachWorks pattern). “Needs teacher” demos pinned to the top with a one-click assign.

Classes / Schedule 🟡

Default to a week calendar (colour by subject), with a list fallback. Each class shows the calendar-sync chip (✓ synced / ⚠ no invite). Inline “mark attendance” from the calendar cell. Filter by teacher / subject / student.

Homework 🟢

Split: completion-rate line (per class over weeks) + a table of assignments with a status pill. Row → submissions with inline grade + comment. Overdue count as a KPI.

Assessments 🟡

Grade-trend multi-line (per subject vs class average) + topic/section drill-down to find weak areas (Edmingle). Optional percentile/cohort benchmark. Result-slip preview keeps the 3 labelled items.

Reports 🟡

Turn into a categorised report library (Fees · Admissions · Attendance · Academics), each a card that opens a focused view — not one page. Keep the month-end parent-report preview here. Admissions-funnel + lost-reasons live here too.

Fee Vouchers 🟢

KPI trio Collected / Pending / Overdue + a paid-vs-pending-vs-overdue stacked bar. Table with status pills; row quick-actions: + Payment, Refund, Fee-decision. Instalment tracking; overdue rows flagged red.

Payments Ledger 🟢

Keep read-only, but add a collection-over-time area line at the top and a method breakdown (bank / cash / wallet). Export + date-range filter. Receipt drawer in place.

Teacher Payouts 🟢

Per-teacher earned vs paid this month (horizontal bars), a “to pay” total KPI, and a one-click Pay with method. Payout history drawer.

Announcements 🟢

Composer + a role-target selector (All / Students / Teachers) once targeting is wired. Feed of posted notices with read reach. Support rule-based pushes (overdue, absentee) as “automated” items.

Email Queue 🟢

KPIs: queued / sent today / failed / daily-cap remaining. A sent-over-time line, status pills, and a manual “run now” (already cron-driven). Failed rows show last error + retry.

Marketing 🟡

Source-attribution donut + cost-per-lead / cost-per-enrol trend, spend vs enrolments. Channel table sorted by ROI.

Settings 🟢

Group into sections (Academy · Branding · Fees & Grace · Integrations · Automation). Remove or wire the disabled “reference only” fields before launch. Show integration health (Google, Resend, cron last-run).

Audit Log 🟢

Timeline view with actor avatars, action colour-coding, and a search + filter by table/actor/date. Keep it read-only.

5 · Manager — the operations view

The manager gets the same components as admin, minus the money internals (payouts, ledger, settings, audit). Their dashboard is operational: people, admissions and schedule — the things they run day to day.

Manager dashboard

KPI row: Active Students · New Leads Today · Demos Needing Teacher · Conversion % · Classes Today · At-risk. Then the admissions funnel + today’s schedule + the same attention feed (minus finance items). Fee amounts collapse to a status count, not rupee figures.

What differs from admin

Same Students / Teachers / Leads & Demos / Booking / Classes / Homework / Assessments / Reports / Announcements — identical UI. Hidden: Payments, Vouchers, Teacher Payouts, Settings, Audit, Email Queue. Reports show operational + admissions categories, not the finance category.

Because the manager reuses admin’s components, this role is essentially free once admin is built — just role-gated visibility. Build admin well and the manager inherits it.

8 · Suggested rollout (biggest perception per hour)

Phase 1 · cheap wins 🟢

  • Bento grid on a strict spacing scale
  • KPI stat tiles: number + trend + sparkline
  • Hover lift + count-up numbers + one staggered entrance
  • Segmented time toggles + row quick-actions
  • Single-CTA empty states everywhere
  • Sidebar regroup into People / Academics / Finance / Comms / System

Phase 2 · medium 🟡

  • Recharts + shadcn charts: area-line + target, funnel, sparklines
  • Skeleton loaders wired to Suspense / loading.tsx
  • Chart draw-in + crosshair + tooltips
  • Cmd-K command palette
  • Teacher inline attendance + grading; per-role dashboards
  • Seeded demo data + onboarding checklist for “wow on first login”

Phase 3 · investments 🔴

  • Click-to-drill-down with URL-param filter state
  • Multi-view toggle (list / calendar / kanban) on Students, Leads, Schedule
  • Inline editing with optimistic UI
  • Drag-and-drop pipeline kanban & widget reorder
  • Small-multiples comparisons; rule-based alert engine
Cross-cutting: grayscale-first hierarchy · tabular-nums on every figure · prefers-reduced-motion guards on all motion · test empty states at 375px · charts themed via CSS vars for automatic dark mode.

Recommended first slice to feel the change fast: rebuild the Admin dashboard as a bento grid with KPI tiles + one area-line + the funnel + the attention feed, add count-up + hover + skeletons. That single screen is the “wow”, and its components then propagate to every other role and tab.
